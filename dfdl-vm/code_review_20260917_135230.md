## Technical Review Findings & Verification

### 1. Simple Type Parsing & Validation
- **Explicit Length Bit Sufficiency:** Added pre-check `bits_available_in_cursor(cursor) < bit_len` in `src/vm/decoder.rs` to ensure complex elements with explicit length return proper `InsufficientBits` error when truncated, rather than child element misdiagnoses.
- **Calendar Parsing:** Fixed text calendar implicit pattern validation when `calendarPatternKind="implicit"` or `calendarPattern` is omitted in `src/vm/runtime.rs`. Ensured diagnostic strings match standard DFDL `Failed to parse xs:{type}` formatting.

### 2. OutputValueCalc & XML Schema Type Casts
- **Precomputation & Pre-evaluation:** Resolved issue where `dfdl:outputValueCalc="{ xs:date(...) }"` resulted in circular dependency errors. In `src/schema/parser.rs`, stored `output_value_calc_literal` for conditional/expression OVCs so expressions can be dynamically evaluated during precomputation.
- **Type Casts:** Extended `eval_xpath_output_value_calc` in `src/vm/encoder.rs` to support `xs:date`, `xs:dateTime`, `xs:time`, `xs:integer`, `xs:long`, `xs:short`, `xs:byte`, `xs:unsignedInt`, `xs:unsignedShort`, `xs:unsignedLong`, `xs:decimal`, `xs:float`, and `xs:double`.

### 3. PUA Control Character Trimming
- **Pad Character Remapping:** Updated `trim_pad_char_for_justification` in `src/vm/runtime.rs` to handle both XML-to-PUA (`alt_pad`) and control-char-to-PUA (`pua_pad`) remappings, allowing PUA-mapped control characters (such as `&#x15;` NAK) to be correctly trimmed according to DFDL text padding rules.
