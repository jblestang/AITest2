## 2. Domain & Language Expertise Review

### A. DFDL Specification & Schema Design (Domain Expertise)
- **Separation of XSD Restriction Facets vs `dfdl:assert testKind="pattern"`:**
  - *Observation:* Previously, `dfdl:assert testKind="pattern" testPattern="..."` and XSD restriction `<xs:pattern>` facets were both stored in `facet_pattern_groups`.
  - *Standard Conformance:* In DFDL 1.0, XSD restriction facets are post-parse validation checks, whereas `dfdl:assert` expressions are pre/post-parse processing assertions. Storing them separately in `assert_test_pattern` prevents XSD `xs:pattern` restrictions on simple types from falsely triggering assertion failure error messages during decoding.
- **Particle Discriminators on IVC Elements:**
  - *Observation:* Added `validate_particle_discriminator` evaluation to elements decoded via `dfdl:inputValueCalc`.
  - *Standard Conformance:* Calculated elements with `dfdl:discriminator` or `dfdl:assert` must evaluate their particle assertions after value calculation so choice branch commitment and assertion verification operate consistently.

### B. Rust Software Architecture & Safety (Development Expertise)
- **No-Panic Safety:** All modified functions return `Result<T, Error>` and propagate errors via `?`. No `panic!`, `unwrap()`, or `expect()` were added in non-test VM code.
- **Memory Efficiency (`no_std + alloc` compatibility):** `assert_test_pattern` uses `Option<StringId>` in `IrProps`, adding only an optional 4-byte `StringId` index rather than copying heap strings.
- **Compilation & Warnings:** Code compiles cleanly under Rust 2021 without warnings.
