## 2. Technical Root Causes & Fix Rationale

### A. Document Load Error Propagation (`src/tdml/parser/document.rs`)
- **Root Cause**: When a TDML test case contained an invalid document (e.g. `BitOrderInvalid.tdml` testing document bitOrder mixture constraints), `parse_document` returned `Err(...)` directly, causing `parse_tdml` to fail the entire file load.
- **Fix**: Wrapped part parsing and document-level bitOrder validation in a catch block that populates `TdmlDocument.load_error: Some(String)` instead of failing suite parsing. This allows TDML test runner to match the captured load error against expected test errors (`<tdml:errors>`).

### B. Bit Cursor Effective Field Bit Order (`src/vm/runtime/cursor.rs`)
- **Root Cause**: `BitCursor::effective_field_bit_order` previously ignored `transmission_bit_order` and `tdml_bit_order_regions`, always returning the schema default order.
- **Fix**: Updated `effective_field_bit_order` to check `tdml_bit_order_regions` and `transmission_bit_order` override first before falling back to `schema_order`.

### C. IR Builder Validation Wiring (`src/ir/builder/element.rs`, `src/ir/builder/mod.rs`)
- **Root Cause**: Validation helpers `validate_bit_order_byte_order` and `validate_program_sequence_bit_orders` were defined but not invoked during IR construction.
- **Fix**: Added explicit calls to `validate_bit_order_byte_order` in `element.rs` and `validate_program_sequence_bit_orders` in `mod.rs`.
