## 2. Technical Findings & Root Cause Analysis

### A. TDML Document Parsing (`src/tdml/parser/document.rs`)
- **Issue**: In `parse_tdml_document`, when assembling document parts composed of mixed `bits` and `hex`/`byte` parts, `saw_bits_part` triggered switching to bit-assembly mode (`bit_part_chunks`). However, hex document parts (`DocumentKind::Hex`) had `bit_chunks = None`. As a result, hex part bytes were pushed to `pending_bits` but omitted from `bit_part_chunks`. When `assemble_tdml_document_bytes(&bit_part_chunks, ...)` was called, only the bits parts were concatenated, dropping the hex part's bytes entirely.
- **Fix**: Formatted each byte of `part.data` into an 8-bit MSB string (`alloc::format!("{:08b}", b)`) and pushed the resulting bit chunks into `bit_part_chunks` when `saw_bits_part` is `true`.
- **Domain Review (Development & Protocol Parsing)**: Clean bitwise concatenation respecting MSB/LSB bit order and alignment unit definitions.
