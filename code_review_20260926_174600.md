## 2. Technical Domain & Expertise Review

### 2.1 DFDL 1.0 Specification Compliance (Discriminators & Choice Branches)
- **Nested Sequence Discriminators in Choice Branches:**
  Under DFDL 1.0 Section 7 (Discriminators), a `dfdl:discriminator` placed inside a model group resolves the nearest enclosing Point of Uncertainty (PoU) — which for choice branch elements is the `<xs:choice>`. When a discriminator on a nested sequence evaluates to `false`, it triggers a parse error that causes backtracking out of the branch.
- **Choice Branch Infoset Representation:**
  When a choice branch is a complex element (e.g. `<xs:element name="a2">`), the resulting XML infoset must retain the `<a2>` wrapper element containing its child elements (`<single>` and `<extra>`).
  Conversely, when a choice branch is an anonymous `<xs:sequence>`, its child elements (`<x>`, `<y>`) appear directly under the choice's parent element without adding a synthetic wrapper.
- **`xs:appinfo` Source Attribute Rule (Section 6.1):**
  The DFDL specification mandates that an `<xs:appinfo>` annotation without a `source` attribute (or with a non-DFDL URI) MUST be ignored for DFDL annotation purposes while issuing a Schema Definition Warning (`xs:appinfo without source attribute`).

## 3. Detailed Changes & Architecture Rationale

### 3.1 Infoset Generator Choice Branch Unwrapping
- **File Modified:** [`src/tdml/infoset/mod.rs`](file:///Users/jean-baptiste/Documents/AITest2/dfdl-vm/src/tdml/infoset/mod.rs#L762-L779)
- **Problem:** `choice_branch_fields_for_infoset` previously returned `seq.fields` directly for any `DfdlValue::Sequence`, regardless of whether `discriminator` held a non-empty branch element name (e.g., `"a2"`). This stripped the `<a2>` element wrapper, leading to `child count mismatch for a2: expected 1, got 0`.
- **Fix:** Restricted sequence field unwrapping in `choice_branch_fields_for_infoset` strictly to cases where `discriminator` is empty (`discriminator.is_empty()`). When `discriminator` is non-empty (e.g., `"a2"`), the element wrapper is retained, mapping `a2` to `DfdlValue::Sequence(...)`.

### 3.2 Appinfo Source Attribute Warning & Exclusion
- **File Modified:** [`src/schema/parser/document.rs`](file:///Users/jean-baptiste/Documents/AITest2/dfdl-vm/src/schema/parser/document.rs#L1237-L1248)
- **Problem:** When an `<xs:appinfo>` tag lacked a `source` attribute, `XsdParser` issued a warning but still executed DFDL annotations inside it (e.g., `<dfdl:discriminator testKind="pattern" testPattern="."/>` in `MissingAppinfoSource.dfdl.xsd`). This caused 0-byte document tests to fail unexpectedly.
- **Fix:** Added `self.skip_element_body(&local)?; continue;` when `source.is_none()`. This ensures the warning `xs:appinfo without source attribute` is recorded while ignoring non-DFDL appinfo content per DFDL 1.0 specification rules.

### 3.3 Choice Branch Discriminator Lookup
- **File Modified:** [`src/vm/decoder/choice.rs`](file:///Users/jean-baptiste/Documents/AITest2/dfdl-vm/src/vm/decoder/choice.rs#L361-L378)
- **Fix:** Restored `branch.branch_key` lookup in `choice_branch_discriminator_for_infoset` to preserve choice dispatch key matching (`dfdl:choiceBranchKey`) across multi-file namespace tests.
